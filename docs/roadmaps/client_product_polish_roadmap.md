# Роадмапа клиентской доработки UnityAid после перехода к SaaS

## 1. Контекст

Два предыдущих роадмапа закрывали разные задачи:

- `development_roadmap.md` довел приложение до дипломного MVP: роли, организации, волонтеры, мероприятия, заявки, учет часов, задачи, новости, геймификация, аналитика, уведомления, база знаний, обратная связь, сертификаты, аудит и документация.
- `saas_product_roadmap.md` перевел продукт в модель managed single-tenant SaaS: отдельный stack на клиента, control plane, provisioning, домены, backup/restore, обновления, мониторинг, feature flags, on-prem пакет и базовое брендирование.

При переходе к SaaS основное внимание действительно было на серверной, эксплуатационной и упаковочной части. Клиентская ценность внутри tenant-приложения почти не пересобиралась под новый тип продукта. Поэтому следующая дорожная карта должна быть не про инфраструктуру, а про то, как заказчик, координатор, руководитель и волонтер реально используют систему каждый день.

## 2. Что уже выполнено

### Базовый рабочий продукт

Готовы основные пользовательские модули:

- авторизация, регистрация, refresh token, восстановление пароля, подтверждение email;
- пользователи, волонтерские профили, навыки, статусы и роли;
- организации, участники организаций и роли внутри организации;
- мероприятия, заявки, лимиты, лист ожидания, смены и завершение мероприятия;
- учет посещаемости и волонтерских часов;
- задачи, исполнители, комментарии, вложения, статусы и учет времени;
- новости с категориями, черновиками, публикацией по расписанию и изображениями;
- геймификация, достижения, баллы, уровни и лидерборд;
- аналитика MVP: обзор, волонтеры, мероприятия, задачи, начисления и действия сотрудников;
- уведомления внутри приложения;
- база знаний;
- обратная связь по мероприятиям;
- сертификаты и справки с PDF и публичной проверкой;
- аудит изменяющих действий;
- системная админ-панель;
- документация запуска, API overview, ER-диаграмма, пользовательское и админское руководство.

### SaaS и поставка

Готова базовая продуктовая инфраструктура:

- отдельный клиентский Docker Compose stack;
- control plane MVP;
- provisioning клиента;
- доменная маршрутизация;
- версионирование и dry-run обновлений;
- backup/restore и история backup;
- опциональный Redis и worker;
- тарифы, лимиты и feature flags;
- export/import клиента;
- health checks и эксплуатационные скрипты;
- security operations клиентского stack;
- on-prem package builder;
- MVP клиентского брендирования через control plane config;
- базовый QR field ops MVP;
- продуктовые документы для продаж, SLA и панели руководителя.

## 3. Главный вывод

Технически продукт уже похож на поставляемый managed SaaS. Функционально он все еще во многом выглядит как расширенный дипломный MVP: есть много модулей, но не хватает клиентской завершенности, управленческих сценариев, гладкого onboarding, отчетов, bulk-операций, шаблонов, настройки процессов и качества интерфейса на уровне продукта, который продается организации.

Новая цель: превратить tenant-приложение из набора модулей в готовое рабочее место клиента.

## 4. Целевые пользователи клиентской версии

### Client owner

Главный администратор клиента. Ему нужны настройка пространства, пользователи, роли, бренд, филиалы, лимиты, документы, отчеты и контроль рисков.

### Руководитель программы

Ему нужны KPI, динамика, проблемные зоны, выгрузки для руководства и грантодателей.

### Координатор

Ему нужны быстрые операции: создать мероприятие, набрать участников, отметить посещаемость, закрыть часы, выдать сертификаты, назначить задачи, видеть просрочки.

### Волонтер

Ему нужны понятный профиль, доступные мероприятия, свои заявки, задачи, часы, достижения, уведомления и документы.

## 5. Релиз 1.0 Client Ready

Цель: сделать текущий функционал безопасным и удобным для первого реального клиента.

### Новый функционал

- Мастер первичной настройки клиента после первого входа:
  - название и описание организации;
  - логотип и цвета;
  - часовой пояс;
  - контактные данные;
  - первый филиал или подразделение;
  - приглашение первых сотрудников.
- Приглашения пользователей по email или одноразовой ссылке.
- Импорт волонтеров из CSV/XLSX.
- Экспорт основных списков в CSV/XLSX:
  - волонтеры;
  - мероприятия;
  - заявки;
  - часы;
  - задачи;
  - сертификаты.
- Роли client owner и staff admin внутри tenant-приложения, чтобы не смешивать клиентское администрирование с системным super admin.
- Страница "Пространство клиента":
  - бренд;
  - подразделения;
  - контакты;
  - рабочие настройки;
  - включенные модули.
- Переработанная страница "Настройки" как каталог настроек продукта:
  - вместо страницы только с управлением правами и кнопкой перехода в системную админку;
  - карточки или кнопки перехода в настройки отдельных модулей;
  - быстрый доступ к настройкам организации, пользователей, ролей, мероприятий, заявок, задач, уведомлений, сертификатов, базы знаний, геймификации, аналитики и файлов;
  - видимость разделов зависит от роли пользователя и включенных модулей клиента;
  - системная админ-панель остается отдельным пунктом только для super admin.

### Фикс багов и технический долг

- Убрать расхождения в документации: в `implemented_functionality.md` раздел ограничений все еще говорит, что сертификаты, Swagger и часть security hardening не реализованы, хотя ниже сертификаты уже описаны как готовые.
- Проверить все переходы после удаления сущностей: организация, мероприятие, задача, новость, статья, сертификат.
- Пройти сценарии доступа для ролей `client_owner`, `org_admin`, `coordinator`, `volunteer`, `support`, `super_admin`.
- Проверить пустые состояния списков и ошибки API на всех основных страницах.
- Проверить загрузку файлов: размер, тип, ошибки, удаление неиспользуемых файлов.
- Проверить часовые пояса в датах мероприятий, дедлайнах задач, scheduled news и отчетах.

### Полировка старого функционала

- Единые статусы и бейджи для заявок, задач, волонтеров, мероприятий и сертификатов.
- Единые фильтры, поиск и пагинация во всех списках.
- Массовые действия:
  - подтвердить несколько заявок;
  - отклонить несколько заявок;
  - отметить посещаемость;
  - подтвердить несколько записей времени;
  - выдать сертификаты группе.
- Улучшить карточки деталей:
  - мероприятие: участники, заявки, смены, часы, отзывы в одном рабочем сценарии;
  - волонтер: профиль, часы, заявки, задачи, сертификаты, достижения;
  - организация: участники, роли, события, задачи, отчеты.
- Добавить нормальные empty states без технических заглушек.
- Привести страницу настроек к роли "центра администрирования":
  - убрать ощущение технической страницы;
  - сгруппировать настройки по смыслу;
  - показать короткое описание каждого раздела;
  - добавить состояние "нет доступа" для скрытых или недоступных настроек.

### Acceptance criteria

- Новый клиент может самостоятельно пройти первичную настройку.
- Администратор клиента может с одной страницы перейти к настройкам нужного модуля.
- Координатор может провести полный цикл мероприятия без обращения к системному администратору.
- Руководитель может выгрузить базовый отчет по часам и мероприятиям.
- Волонтер видит свои заявки, задачи, часы, сертификаты и уведомления без перехода в админские разделы.

## 6. Релиз 1.1 Операционная эффективность

Цель: снизить ручной труд координаторов и администраторов.

### Новый функционал

- Шаблоны мероприятий:
  - типовые поля;
  - повторяемое расписание;
  - стандартные смены;
  - типовой набор задач.
- Повторяющиеся мероприятия.
- Конструктор заявки на мероприятие:
  - дополнительные вопросы;
  - согласия;
  - ограничения по возрасту, навыкам, организации или городу.
- Автоматические правила обработки заявок:
  - автоодобрение при свободных местах;
  - перевод в лист ожидания;
  - отказ при несоответствии критериям;
  - уведомление координатора о спорных заявках.
- Расписание волонтера:
  - мои ближайшие мероприятия;
  - мои смены;
  - мои дедлайны задач.
- Календарный вид мероприятий и задач.
- Bulk import задач и мероприятий.

### Фикс багов и надежность

- Защитить от двойной подачи заявки на мероприятие.
- Защитить от двойного начисления часов при повторном завершении мероприятия.
- Проверить корректность листа ожидания при изменении лимита участников.
- Проверить пересчет геймификации при изменении часов, отмене участия и удалении задачи.
- Добавить транзакционность в сценарии, где одновременно меняются заявка, часы, уведомление и геймификация.

### Полировка старого функционала

- Быстрая панель координатора на странице мероприятия:
  - новые заявки;
  - ожидают решения;
  - подтверждены;
  - не пришли;
  - часы требуют подтверждения.
- Быстрые действия из списков без открытия детальной страницы.
- Улучшенные уведомления:
  - группировка;
  - приоритет;
  - настройки типов уведомлений;
  - email-уведомления для ключевых событий.

### Acceptance criteria

- Координатор создает типовое мероприятие за несколько минут из шаблона.
- Большинство рутинных заявок обрабатываются автоматически по правилам.
- Волонтер видит свое расписание и не теряет задачи или мероприятия.

## 7. Релиз 1.2 Управленческая ценность

Цель: дать заказчику понятный ответ, зачем он платит за систему.

### Новый функционал

- Полноценная панель руководителя:
  - активные волонтеры;
  - подтвержденные часы;
  - мероприятия за период;
  - закрытые задачи;
  - динамика активности;
  - эффективность координаторов;
  - топ организаций или филиалов;
  - проблемные зоны.
- Отчеты:
  - для руководства;
  - для грантодателя;
  - по филиалам;
  - по сотрудникам и координаторам;
  - по волонтерам;
  - по сертификатам;
  - по просроченным задачам и неподтвержденным часам.
- Экспорт отчетов в PDF и XLSX.
- Сохраненные фильтры отчетов.
- Плановая отправка отчетов на email.
- Настраиваемые KPI клиента:
  - целевые часы;
  - целевое число активных волонтеров;
  - целевое число мероприятий;
  - SLA обработки заявок.

### Фикс багов и качество данных

- Единая методика подсчета активного волонтера.
- Единая методика подсчета подтвержденных часов.
- Исключение дублей в отчетах по мероприятиям, задачам и сертификатам.
- Проверка прав доступа к отчетам по организации и филиалу.
- Аудит экспорта отчетов.

### Полировка старого функционала

- Графики заменить с простых MVP-визуализаций на читаемые управленческие виджеты.
- Добавить drill-down: из KPI можно перейти к списку сущностей, которые сформировали показатель.
- Добавить пояснения к метрикам в интерфейсе без перегруза экрана.

### Acceptance criteria

- Руководитель открывает один экран и видит состояние волонтерской программы.
- Отчет для грантодателя можно сформировать без ручной сборки в таблицах.
- Все цифры в отчете можно объяснить через исходные записи.

## 8. Релиз 1.3 Полевой учет в web-интерфейсе

Цель: сделать учет участия удобным на мероприятии без разработки отдельного мобильного приложения.

### Новый функционал

- QR check-in/check-out в web-интерфейсе:
  - генерация QR для мероприятия и смены;
  - сканирование через браузер на устройстве координатора;
  - фиксация времени входа и выхода;
  - ручная корректировка координатором.
- Быстрая регистрация участника на месте через web-форму.
- Публичная страница мероприятия для набора волонтеров.
- Печатный список участников с QR/кодом мероприятия как резервный сценарий.

### Фикс багов и безопасность

- Ограничить срок жизни QR-токенов.
- Защитить QR от повторного использования вне допустимого окна.
- Логировать ручные корректировки посещаемости.
- Проверить web-сценарий регистрации, отметки и корректировки посещаемости на типовых рабочих устройствах координатора.

### Полировка старого функционала

- Собрать действия на мероприятии в отдельный рабочий экран координатора.
- Сократить количество переходов для отметки участника, корректировки часов и закрытия смены.
- Добавить понятные состояния после сканирования: успешно, уже отмечен, токен истек, нет доступа.

### Acceptance criteria

- Координатор может отметить участников через web-интерфейс на месте проведения.
- Координатор может на месте увидеть список пришедших и отсутствующих.
- Часы попадают в систему без ручного переноса из таблиц.

## 10. Релиз 1.5 Настраиваемые процессы клиента

  - типы мероприятий;
  - направления помощи;
  - навыки;
  - причины отказа;
  - типы документов.
- Конструктор полей профиля волонтера.
- Конструктор форм для заявок, обратной связи и регистрации.
- Простые workflow-правила:
  - при подтверждении заявки отправить уведомление;
  - при завершении мероприятия запросить отзыв;
  - при достижении часов предложить сертификат;
  - при просрочке задачи уведомить координатора.

### Фикс багов и надежность

- Не ломать существующие данные при изменении схемы кастомных полей.
- Валидировать динамические формы на backend.
- Ограничить доступ к настройке процессов только клиентским администраторам.
- Проверить права доступа для каждого раздела `/settings/*`.
- Не показывать пользователю ссылки на настройки модулей, к которым у него нет доступа.
- Не дублировать системную админ-панель внутри клиентских настроек.

### Полировка старого функционала

- Свести настройки в один понятный раздел "Администрирование клиента".
- Убрать из клиентского интерфейса технические элементы, нужные только системному super admin.
- Добавить предпросмотр форм и документов перед публикацией.
- Сделать страницу настроек визуально похожей на каталог разделов, а не на одну длинную форму.
- Добавить поиск по настройкам.
- Добавить breadcrumbs внутри вложенных настроек модулей.

### Acceptance criteria

- Клиент может адаптировать продукт под свои процессы без правок кода.
- Изменения настроек не затрагивают другие клиентские stack.
- Пользователи видят только включенные для клиента модули.
- Страница `/settings` содержит переходы к настройкам отдельных модулей.
- Каждый раздел настроек имеет понятную зону ответственности и не требует перехода в системную админку для обычных клиентских изменений.

## 12. Definition of Done для Client Ready

Версия считается готовой для первого клиента, если:

- клиент может быть создан через control plane и получить рабочий URL;
- client owner может настроить пространство без разработчика;
- сотрудники клиента могут быть приглашены или импортированы;
- волонтерский путь проходит от регистрации до сертификата;
- координаторский путь проходит от создания мероприятия до закрытия часов;
- руководитель получает отчет по периоду;
- ключевые списки экспортируются;
- роли и доступы проверены приемочными сценариями;
- все критичные действия пишутся в аудит;
- интерфейс не содержит технических заглушек на основных страницах;
- есть понятный demo-сценарий для продажи и пилота.
